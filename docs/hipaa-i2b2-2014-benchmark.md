# SecuRedact on the 2014 i2b2/UTHealth De-identification Benchmark (Track 1)

**Status: HARNESS COMPLETE — OFFICIAL TEST RUN BLOCKED (authorized corpus not available locally).**

This document is the protocol and results record for an external, fair, reproducible
de-identification benchmark of SecuRedact against the **2014 i2b2/UTHealth De-identification
Challenge (Track 1)**, and against **Phileas/Philter 3.4.1** under its strongest legitimate
configuration. The objective is *not* to make SecuRedact win, but to determine whether it
actually wins under fair, frozen-test conditions.

No restricted clinical text appears in this document. All numbers for the official test set
are `PENDING` until an authorized local copy of the corpus is supplied.

harness). In short:

* **Training corpus** — de-identified training notes with gold PHI annotations (surrogate

  inline `<PHI TYPE="…">` tags (or `start`/`end` offsets).
* **Test corpus** — held-out test notes with gold PHI. Published size **514 notes**. Place
  under `…\i2b2-2014\test\`. **Treated as frozen.**
* **Official scorer (optional, for canonical validation)** — `kotfic/i2b2_evaluation_scripts`
  tag `v1.2.1` (Apache-2.0, public). Our harness faithfully reproduces its metrics; this is

## 3. DUA / access limitations

* The corpus is restricted; only an authorized requestor may obtain it.
* No note text is printed in full, committed to git, or sent to any cloud API.
* IDs and aggregate statistics only are used in repository documentation.
* The benchmark harness refuses to run unless both `training/` and `test/` exist locally.

## 4. Train / dev / test methodology

* **Training**: 790 notes (official). We never tune on test.
* **Dev**: deterministic 80/20 split of the *training* note IDs only, fixed seed
  (`i2b2-2014-securedact-dev-v1`), recorded in `dev_tuning.json` (note IDs only, no text).
  Used for: confidence-threshold selection, gated-category selection, adapter validation,
  label-mapping verification.
* **Test**: 514 notes, frozen. A `test_run.lock` file prevents accidental re-runs.

## 5. SecuRedact deterministic configuration (frozen)

* Engine: `build_production_engine(require_contextual=False)` → `CredentialsDetector`,
  `RegexDetector`, `ContextualPrivacyDetector` (rule layer, `contextual=False`), policy
  `hipaa_safe_harbor`.
* No model load; fully deterministic, fail-closed.
* Structured identifiers (SSN, phone, fax, email, URL, IP, MRN-like, etc.) are detected
  deterministically and are **never** overridden by contextual NER.

## 6. Contextual model configuration (frozen)

* Model: **Flair NER English Large** (`flair/ner-english-large`,
  revision `e2b1caabf7f9bac1e7829db73eac734df7e6ad7b`), CPU.
* Tag map (Flair → SecuRedact): `PER/PERSON→PERSON`, `LOC/GPE→LOCATION`,
  `ORG→ORGANIZATION`, `DATE→DATE`, `ADDRESS→ADDRESS`, `MEDICAL/DISEASE→MEDICAL`.
* Candidate contextual categories gated into the ensemble: **NAME** and **LOCATION**
  (HIPAA A and B). Other categories remain deterministic.

## 7. Contextual runtime / environment solution

Windows **WDAC blocks `torch` `shm.dll`**, so the Flair model cannot load on the Windows
host. We do **not** weaken WDAC. Instead the contextual model runs in an authorized
**WSL2 (Ubuntu 24.04)** or a **local CPU Docker** container, with model weights mounted
**read-only** from `<local-model-cache>`. No clinical text leaves the machine; no cloud
inference is used. See `scripts/experimental/i2b2_2014/runtime_env.py` for the exact launch
commands (`python -m scripts.experimental.i2b2_2014.runtime_env`).

## 9–13. Evaluation modes, Phileas config, taxonomy, methodology

All implemented in the harness:

* Modes: **A** deterministic, **B** contextual-only (Flair-sourced), **C** blind union
  (research only), **D** precision-gated ensemble (primary SecuRedact candidate).
* Phileas: `philterd/philter:3.4.1`, policy `hipaa-bench`, every PHI/PII filter mapped to a
  Safe Harbor category enabled, `REDACT` strategy, no confidence gating (raw recall
  measurement), local Docker only.
* Taxonomy mapping: `mapping.py` (i2b2 ↔ HIPAA A–R ↔ SecuRedact `EntityType` ↔ Phileas),
  every row classified `direct / approximate / unsupported / excluded`.
* Scorer: `scorer.py` — token-level and entity-level micro-averaged P/R/F1 over three PHI
  definitions: full **i2b2-PHI**, the **HIPAA-PHI** subset (Stubbs et al. 2015), and
  **binary PHI**. Primary ranking metric = micro-averaged **entity-based F1 on i2b2-PHI**,
  matching the official challenge.

### i2b2 ↔ HIPAA ↔ SecuRedact mapping (summary)

| i2b2 category (type) | HIPAA? | SecuRedact entity | Class |
|---|---|---|---|
| NAME (PATIENT/DOCTOR/FAMILY/EMPLOYEE) | PATIENT only | `PERSON` (A) | direct |
| PROFESSION | no | — (none) | unsupported |
| LOCATION (STREET/CITY/ZIP) | yes | `STREET_ADDRESS`/`LOCATION`/`US_ZIP` (B) | direct |
| LOCATION (STATE/COUNTRY/HOSPITAL/DEPT/ROOM) | no | `LOCATION`/`ORGANIZATION` | approximate |
| LOCATION (ORGANIZATION) | yes (i2b2 HIPAA) | `ORGANIZATION` | approximate |
| AGE | yes | `AGE` (C) | direct |
| DATE | yes | `DATE`/`DATE_OF_BIRTH` (C) | direct |
| CONTACT (PHONE/FAX/EMAIL) | yes | `PHONE`/`FAX`/`EMAIL` | direct |
| CONTACT (URL/IP) | no | `URL`/`IPV4` | direct |
| ID (SSN/MRN/HEALTH PLAN/ACCOUNT/LICENSE/VEHICLE/DEVICE/BIOMETRIC/ID NUMBER) | yes | G/J/H/I/J/K/L/M/P/R | direct/approx |
